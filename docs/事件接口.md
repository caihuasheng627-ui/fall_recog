# 事件接口

识别程序发给同学 B 的消息。前期 B 用模拟消息开发，字段名不要改。

一条 JSON 一行，UTF-8。

```json
{"device_id":"ws63-1","t_ms":12840,"frame_id":642,"state":"suspect","action":"fall","reason":"fast_then_still","rng":120,"vel":0,"human":1}
```

| 字段 | 含义 |
|---|---|
| `device_id` | 设备号，默认 `ws63-1` |
| `t_ms` | 触发这一状态的帧时间 |
| `frame_id` | 对应帧序号 |
| `state` | `normal`、`suspect`、`alarm` |
| `action` | 疑似和报警时为 `fall`，正常时为 `none` |
| `reason` | 见下表 |
| `rng` | 该帧距离原值 |
| `vel` | 该帧速度原值，保留正负 |
| `human` | `0` 或 `1` |

`state`：

| 值 | 含义 |
|---|---|
| `normal` | 无人，或有人但没有构成跌倒 |
| `suspect` | 已经出现带距离变化的快速冲击，并且随后停在落点附近 |
| `alarm` | 静止继续超过确认时间，升级为报警 |

`reason`：

| 值 | 何时出现 |
|---|---|
| `idle` | 一段记录的第一条，当前还是正常 |
| `fast_then_still` | 进入疑似或报警 |
| `recovered` | 疑似之后距离回到冲击前，或人又持续移动，回到正常 |
| `no_human` | 尚未形成冲击时，人离开超过约 0.8 秒，回到正常 |
| `cleared` | 收到解除命令 |

报警会锁存。人还躺在检测区里时，不会自己再发一条新的报警，也不会因为轻微噪声或 `human=0` 取消。冲击已经开始后，短暂丢人不取消这次冲击。

解除由 B 回传一行 JSON，识别侧从 `apply_uplink` 进入，不把这行当成雷达帧：

```json
{"device_id":"ws63-1","cmd":"clear"}
```

`device_id` 必须和本机一致，`cmd` 必须是 `clear`。对得上才解除，并输出一条 `state=normal`、`reason=cleared`。对不上就保持原状态。网页状态由 B 更新。

只在状态变化时输出一条，不按帧刷消息。示例见 `results/event_example.jsonl`。

# 数据接口

雷达采集同学按这个格式落盘。识别程序不关心固件里怎么打印，只认文件。

## 文件

一个动作一个 CSV，UTF-8。文件名：

`{人员编号}_{动作}_{序号}_{split}.csv`

例如 `P01_fall_03_test.csv`。

- 人员编号：`P01`、`P02`，从 `P01` 起。
- 动作：`empty` `stand` `walk` `sit` `bend` `lie` `fall`。
- 序号：两位，从 `01` 起。
- `split`：`train` 或 `test`。同一次连续记录不能拆进两边。

同名 `.txt` 是记录表，每个字段一行 `key=value`。模板在 `templates/记录表.txt`。

约定 `P01` 全部作为 `test`，其余人员作为 `train`。

## 列

| 列名 | 含义 | 写法 |
|---|---|---|
| `t_ms` | 本段开始后的毫秒，从 0 严格递增 | 整数 |
| `frame_id` | 帧序号，从 0 严格递增 | 丢帧就跳号，不要重排后假装连续 |
| `gear` | 当前帧档位 | 实板原样保存 |
| `rng` | 距离测量值 | 实板原样保存。`-999` 表示这一帧没有有效距离，识别时丢掉 |
| `vel` | 速度测量值 | 实板原样保存，保留正负。`-999` 表示这一帧没有有效速度，识别时丢掉 |
| `snr` | 信噪比 | 保留 1 位小数 |
| `human` | 是否有人 | `0` 或 `1` |
| `lb` | 距离下边界 | 实板原样保存 |
| `ub` | 距离上边界 | 实板原样保存 |
| `hgt` | 这一帧目标离地高度 | 可以不写。当前固件回调没有这一项，不要编造。`-999` 或空着表示未知。合成数据用厘米：站立约 150，坐下约 85，躺下约 25 |
| `iq` | 原始 I/Q，20 个距离 bin，I/Q 交替共 40 个整数 | 分类器主特征。用空格分隔。没有这一列时分类器该 20 维为 0。板端需注册 `uapi_radar_register_raw_data_cb` 落盘，不要用合成假峰当实板 |
| `label` | 整段动作 | 与文件名里的动作相同。板端原始日志可以先不写这一列，切段时再补 |

记录表里的 `height_cm` 是受试者身高，识别不拿它当姿态。

第一行是表头。`#` 开头的行是注释，程序会跳过。板端日志请在文件头写上单位，确认之前写 unknown：

```
# source=board rng_unit=unknown vel_unit=unknown frame_period_ms=50
```

SDK 示例把 `0–100` 注释成 1 米档、`100–200` 注释成 2 米档，所以 `lb/ub` 有可能是厘米。这只是推测。第一节点要有人在 1 米和 2 米各站 10 秒，对照 `rng`、`lb`、`ub` 后再改文件头里的单位。`vel` 用走向雷达、远离雷达各走一次，确认正负。

当前帧回调和人体结果回调如果不同步：`human`、`lb`、`ub` 用最近一次结果，但每一帧仍然写一行。不要等结果变化才写，否则静止段会被抽空。

记录间隔不要大于 200 ms，建议 50 ms 或 100 ms。间隔更大时，一次短冲击可能只剩一帧，规则无法把它和噪声分开。

## 检查

在 `src` 目录执行：

```
python -m fall_recog check fall_recog/data/board
```

通过时每段打印 `OK`、帧数和时长。`t_ms` 或 `frame_id` 倒退会失败。间隔大于 250 ms 会警告，不中断。
